# Mac MIT notice mapping and proposed distribution set

This review covers source `8ac67ef0b4d705635734d046f2f3f819b000e284`, product 0.7.5, and the four locked MIT-only packages below. The Rust attribution supplement is included. The updater dependency delta is documented separately in [updater materials](in-app-update-licenses.md). Full terms are already retained; this document maps known notices to actual source and proposes a bounded notice set. It neither invents new grants nor approves SDK redistribution or a final binary. The collector and all fourteen original mandatory review conditions remain unchanged.

## Source-to-notice evidence

The [historical upstream README](https://raw.githubusercontent.com/madsmtm/objc2/757cd841d0293341dbefd9b99d7548dec244ffde/README.md) expressly identifies the merged original projects and their new names. The same revision's [MIT file](https://raw.githubusercontent.com/madsmtm/objc2/757cd841d0293341dbefd9b99d7548dec244ffde/LICENSE.txt) carries Steven Sheldon's existing notice. The later [official MIT document](https://raw.githubusercontent.com/madsmtm/objc2/ee9a7ada2131f5944b8750428e265c15632f2a19/LICENSE-MIT.txt) carries Mads Marquart's notice. Both original files are already retained beside each package. Retain both; replacing the historical notice with the later single-author notice would lose known attribution.

The [complete file map](../scripts/distribution/mac-mit-notice-map.json) records exact official archive checksums, source revisions, every published `src/**` path and source SHA-256, same-path historical Git blob evidence, and four independently checked comparisons. It contains source metadata, not redistributed crate bodies. Archives were checked against the current lock/manifest and their VCS revisions. No SDK was installed and no downloaded crate source was compiled or executed.

For objc2's `src/__macro_helpers/os_version/apple.rs`, the source expressly points to [Rust PR138944](https://github.com/rust-lang/rust/pull/138944). Preserve that attribution alongside the objc2 notices. `tests/no_prelude.rs` credits inspiration from `objrs`; it is outside this runtime-source map. If actual crate test/source archives are added to a distribution, review their extra provenance separately instead of assuming that all crate contents enter the app binary.

A scan of the four published `src` trees found no additional explicit copyright headers. Foundation's three `Copyright` keyword occurrences identify the `NSMetadataItemCopyrightKey` API, rather than a contributor copyright notice. This is a bounded source-inspection result, not proof that no additional rights exist. The inspected four archives contain no native SDK headers, `.tbd`, `.a`, `.lib`, `.dll` or `.dylib` files.

## Minimum retained notice proposal

For a payload containing substantial code from these packages, use the [proposed notice summary](../scripts/distribution/proposals/MAC-MIT-NOTICES.txt) together with the full unchanged texts already retained under each package. The summary is a review draft, not a replacement for those texts:

1. Keep each package identity and its declared MIT terms with the existing Mads Marquart notice.
2. Keep the historical Steven Sheldon MIT notice and permission text for inherited material in all four package groups.
3. Keep the existing Rust MIT attribution for objc2's identified imported implementation; retain COPYRIGHT/REUSE as supporting provenance.
4. Preserve any additional applicable file-level notices found during actual payload review. Do not synthesize years, names, a blanket Apple notice or licenses from a contributors list.

`referenceOnly` excludes historical/reference material from completeness-marker checks; the current collector still copies it into retained supplemental output. The legacy notice is therefore already preserved. No change to that behavior is needed. Source review has now established concrete reasons to keep the legacy and Rust displays. Whether this set exhausts every relevant notice remains an integration/rights assessment, rather than a missing-text retrieval problem. Existing MIT permission is confirmed by [the maintainer's old-version statement](https://github.com/madsmtm/objc2/issues/826#issuecomment-6103078978); no relicensing or new consent from every contributor is proposed. The maintainer's [notice-sufficiency uncertainty](https://github.com/madsmtm/objc2/issues/826#issuecomment-6107377999) is preserved.

## SDK material and actual payload

The four packages are not one kind of input. block2 and objc2 provide Rust ABI/runtime and safety code; objc2-encode supplies encoding logic. Foundation also ships generated Rust types, constants, extern declarations, method wrappers and documentation derived through the header translator. The older 14-package review directly established generation markers in dispatch2 plus nine framework packages; the other four had no generated directory. That distinction does not establish independent origin for every handwritten declaration.

| Proposed payload                                                | Concrete check and consequence                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Original project source with dependency names/version/checksums | Confirm no actual registry sources, generated dependency bindings or SDK payload was copied into tracked vendoring/archive entries. Referencing a dependency is a different payload from shipping its code. Review existing wry/app source and their notices separately; no complete source-publication clearance is inferred here.                                                        |
| Actual crate source or generated bindings                       | Preserve applicable source notices. Generated declarations and copied documentation must be evaluated as source material; the package MIT declaration cannot grant separately owned SDK rights.                                                                                                                                                                                            |
| Self-built app retained by its builder                          | The builder's actual SDK agreement/environment governs SDK use. Sharing the resulting executable introduces distribution obligations; self-build is not SDK redistribution permission.                                                                                                                                                                                                     |
| App binary/bundle                                               | Identify selected/generated code and static inputs, inspect Mach-O dependencies and bundle entries, and preserve applicable notices. System-framework imports are not proof that framework libraries were copied. Rust documentation comments ordinarily differ from emitted object code; actual payload must establish what survives. No current Mac binary was inspected in this review. |

The current [Xcode and Apple SDKs Agreement](https://www.apple.com/legal/sla/docs/xcode.pdf) §2.2 permits development subject to its terms; §2.4 permits compliant macOS applications/libraries to be distributed. §2.5 preserves notices on permitted Apple Software copies. §2.7 restricts SDK parts/derivatives, with law and separately licensed OSS/sample exceptions. Those clauses do not establish that every Rust binding is forbidden or that every API declaration is unprotected. The source reviewer identifies actual generating SDK/component versions and reproduced material; an authorized owner/qualified legal reviewer determines applicability to declarations, wrappers, documentation and any embedded implementation. The current PDF does not prove the historical generating agreement. Account/entity owners alone decide any required new agreement acceptance. No acceptance or contact occurred here.

No gate is relaxed. Future review can use the completed file map and retained notice set instead of restarting generic text collection. Remaining uncertainty is now attached to actual payload coverage and SDK/rights applicability, rather than an assertion that all four packages lack usable MIT material.
