# Restarting with the previous tabs

Mogledge automatically remembers the open tabs for each registered knowledge root: their order, left and right panes, active tabs and pane, document zoom, and the bundled help tab. The same HTML can remain open independently in both panes. Named workspace sets remain a separate, explicit feature. [Display-folder switching](registered-folders.md) leaves this registered root and existing tabs intact; restart never registers the last displayed child as the saved-input root.

When the tabs exceed the available width, use the horizontal scrollbar or horizontal wheel/trackpad input to reach them. Each column scrolls independently. Keyboard navigation, including Home and End, brings the selected tab into view. Blank space after the tabs remains available for moving the window.

On startup, the saved root must first pass the existing root recovery and identity checks. Only visible documents are loaded. Other restored tabs remain placeholders until selected; their HTML, iframe and document grants are not created in advance. Missing files remain marked tabs without blocking the other pane or startup. A replacement file is checked against the saved physical document identity before loading. If a loaded file disappears, its last successfully admitted navigation reference survives grant revocation so layout changes and controlled Quit remain available, including before the first automatic write. This reference does not authorize document reads or saved-input writes; a successful later load must admit the physical file again.

Tab layouts contain document references, not HTML input values or JavaScript state. Save inputs through the document's storage API before quitting. Opening the same tabs again does not restore unsaved inputs, timers, Canvas state or a previous JavaScript heap.

A new tab whose first registration or HTML read fails stays visible with its error, but it has no admitted physical document reference and is omitted from the restart layout. It does not prevent normal Quit or root switching. A successful retry makes it eligible for restoration; later read failures retain its last admitted reference. Existing restored missing-file placeholders remain part of the layout.

Normal Quit and an updater restart create a new process that restores the last successfully saved layout. Tray residency only hides the existing process and retains its live tabs. Switching roots restores the selected root's own layout; references from a different physical root are never reused. Closing all tabs explicitly saves an empty layout, while renderer teardown does not save its temporary empty state. Collapsing two panes retains the hidden pane assignments, and independently opened copies remain distinct even after moving them into the same pane.

Controlled Quit, non-resident window close, updater restart and root switching first wait for a bounded session flush. The main window stays alive for the handshake; only its token-matched acknowledgment is accepted. A timeout or save failure cancels the controlled operation and reports an error instead of forcing termination. Startup recovery exits before the main renderer exists remain available. OS force-termination can recover only the last successful layout.

The main UI debounces automatic layout writes by 200 ms and serializes captures. Explicit controlled-operation flushes bypass that delay. Input keystrokes, document-ready notifications and URL changes do not themselves write a session. Persistence uses the existing no-follow workspace preference directory, stored-hash conflict detection and atomic replacement. A failed read prevents automatic session writes; a failed write preserves the previous successfully stored layout and reports an error. Ordinary workspace preferences keep their existing 256 KiB budget. The separate session file has its own 256 KiB bound and does not inherit the manual workspace set's 30-item limit. A layout that exceeds that bound fails without truncating tabs or discarding saved preferences. Session read/write failures are tracked separately and do not make ordinary favorites or workspace sets read-only.

Ordinary workspace preferences remain in format v4 and continue reading formats v1–v4. Automatic sessions use a separate strict version 1 envelope in the same `workspace-settings` directory. Its 64-digit filename is SHA-256 of the domain tag `mogledge-tab-session-v1`, a zero byte, and the physical root identity. The envelope also validates that root identity and its `tab-session` kind. Older apps that support preference format v4 keep reading and editing their existing physical-root preference file, leaving this independent session file untouched. Retained identity-transition preference decoding and closed-set backup filename validation remain unchanged. Offline database rollback still refuses changed or new preference leaves after its backup; this safety check also applies to session files.

Synthetic tests cover large lazy layouts, pane duplicates, missing references, help position, empty sessions, stale root responses, admission checks and persistence conflicts. A successful unit test is not evidence that device checks passed.

An independent review reproduced a normal-flush failure after a new tab's first HTML read failed. The correction excludes never-admitted tabs and adjusts active/help indices without changing Native identity validation. `npm test -- src/lib/controller.tab-session.test.ts src/features/document-viewer/TabSessionDeck.test.tsx` passed all 18 tests, including first read/registration failures, successful retry without a layout change and a later read failure. `npm run check` passed formatting, types and lint without warnings. The Native binary described below predates this renderer correction; its evidence does not establish the new error-tab behavior on a device.

The isolated QA executable embedded product version 0.8.2 and had SHA-256 `fa2a90cd66b65161d861cbeeca6a2b5cd423e4c0ecf547d8e31fdbbb75d6765f`. Later documentation changes are separate from that binary's build source.

The probe used a dedicated test identifier/profile, 39 synthetic canonical HTML files, Windows UI automation and injected messages to the owned renderer window. It exercised the real Native app and renderer; physical keyboard input was not tested. The e2e bootstrap selected only the synthetic root and bypassed normal Product profile root restoration. Its configuration directory was prepared as part of the fixture; Product startup/root-recovery coverage is separate.

Moving tabs into two panes, saving values 42 and 84, closing the non-resident titlebar window and restarting the same binary restored ordered left Alpha/right Beta tabs, the active right pane and both saved values. After a loaded Gamma file was moved aside inside the synthetic fixture, Rescan revoked its grant; normal window close still completed and preserved its missing reference. Restart restored healthy Alpha with value 42 and the right Gamma missing-file placeholder with pane assignments intact. Gamma was then returned as the same physical file, and all 39 HTML hashes matched the originals. The QA process exited normally, and the current user app and profile were unchanged.

A later Windows WebView2 probe reused that Native binary with the corrected renderer served through HMR, followed by a fresh process restart. A marked synthetic migration-QA profile exercised the shared strict Product startup, profile lease and `Core::restore` path without an e2e root bootstrap. Its settings were prepared using the synthetic directory's actual volume, file ID and creation metadata. Resident close retained the process, the owned tray callback restored it, and the Native tray menu's Quit completed normally. With a new invalid-UTF-8 tab still visible, Quit saved only the admitted Alpha reference; restart restored Alpha and omitted the never-admitted error tab. Both canonical fixture HTML hashes stayed unchanged. This validates these device interactions with the corrected renderer, not a newly linked ordinary release binary or physical pointer/key input.

The Native folder-picker automation selected a different directory during its first attempt. That attempt was stopped without opening or saving HTML, the QA process exited normally, and only the dedicated QA settings were corrected before restart. Picker restoration is not passed by this probe. Ordinary Product-profile startup, Native root switching, macOS behavior, signed updater restart (disabled in e2e), OS force-termination, large layouts and duplicate views on Native, physical keyboard input and power-loss durability remain unverified. Retain these release/device checks separately from the completed Windows tray and shared-startup checks.
