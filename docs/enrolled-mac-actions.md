# Enrolled Mac artifacts without an Actions signing key

This is an explicit distribution build mode, not the ordinary source build. The default configuration and default `updater_app: false` workflow still leave updates disabled. The mode requires the separately reviewed production build-time enrollment correction and final coordinated product revision before execution; the 0.8.0 base used to prepare this script is not an approved final build source.

Use the existing manual **Binary distribution candidates** workflow after integration. Select the owner's Intel architecture with `platform: macos-x64`, `updater_app: true`, the approved complete `expected_source_sha`, and the two cost/material confirmations. The standard `macos-15-intel` runner is selected; updater mode accepts one Mac platform, not Windows or `all`. Keep the owner's $0 additional budget/stop policy and existing payment settings unchanged. No larger runner, paid signing service, Secret or public Release is added.

## Configuration and single compilation

`src-tauri/tauri.updater.distribution.json` is selected only by this explicit mode. It contains the supplied public key, `requireSignedVersion: true`, updater artifacts enabled as a compile-time enrollment decision, and future HTTPS endpoint `https://github.com/shimi-lynx/mogledge/releases/latest/download/latest.json`. The supplied Ed25519 key ID is `834723B673FE6C1E`; SHA-256 of its 32 public bytes is `65b10a703ca58b486328274e88c5999fee34e16c15356d64aa3b19e54dd49a55`. The builder validates the exact public identity and overlay scope. No credential is embedded. Identifier/profile/install identity and ordinary product version remain unchanged.

The repository/feed is still private and no actual signed assets are established. This app is prepared for the future feed; checking can fail while it is unavailable. Do not describe a live service or assume anonymous access to private Releases. Public hosting/publication requires a separate decision.

The builder collects the actual selected `custom-protocol,distribution-updater` Cargo closure and existing npm legal material first. It then:

1. Runs pinned Tauri CLI `build --no-bundle` with the selected target, `distribution-updater`, reviewed distribution overlay and resource mapping, locked dependencies and one Cargo job. This is the only application compilation.
2. Runs `bundle --bundles app` for the already-built binary with the same target/features/configuration, adding only `bundle.createUpdaterArtifacts: false` for this packaging stage. It does not rebuild the runtime enrollment decision. The app retains ad-hoc OS signing; `--no-sign` is not used.
3. Verifies the .app's identity/version/architecture, ad-hoc codesign and executable privacy. All collected third-party texts/notices/required sources, project LICENSE, exact source ZIP and distribution guide are included inside .app Resources, and every retained material file is compared with the staging input.
4. Creates and extracts a `.app.tar.gz` containing that final .app. Codesign, identity, architecture, executable bytes and every bundled material file are checked after extraction. Creates the initial-install candidate ZIP from the same app and material package, and verifies its extracted app too.

The pinned Tauri CLI 2.12.1 source supports this separation: `build.rs` calls bundling only when `no_bundle` is false; `bundle.rs` signs updater packages only for its updater-enabled bundle types, and returns without reading a signing key when none exist. App-only packaging with artifact generation disabled supplies no updater package. This is source-level feasibility evidence, not an actual Mac execution result. The first separately authorized native run must verify the full path; a build/bundle failure is reported without inventing success or repeatedly compiling other platforms.

## Outputs and owner-local signature

A successful run uploads four files for this mode: initial-install candidate ZIP, unsigned-as-an-update `.app.tar.gz`, `SHA256SUMS.txt` listing both archives, and `manifest.json`. The ZIP contains the same complete manifest and initial-install app/materials. The manifest records exact source/version/platform, configuration hash, update-archive/executable/source hashes, requested updater enrollment and pending native acceptance/local update signature. No `.sig` is generated by Actions. An ad-hoc OS signature is separate from an updater signature and does not provide Developer ID/notarization or remove Gatekeeper warnings.

The owner may sign the exact retained `.app.tar.gz` in the approved local signing environment, including on Windows, using the existing updater key. Use the manifest's verified version with CLI `signer sign --app-version`; Tauri signs file bytes and binds that version, independent of the target OS. Keep private key/password handling in that environment through its existing protected procedure; do not pass secrets through chat, committed files, workflow inputs or logs. Only the resulting `.sig`, public metadata and unchanged archive are needed for the future feed. No key generation or signing is performed by this preparation.

Verify the actual artifact signature against the configured public key before treating it as installable. Construct a future static manifest with `platforms.darwin-x86_64.url` for the real HTTPS archive and `signature` containing the generated .sig contents, matching the artifact's signed/product version. Publishing reviewed assets and then the validated manifest is a separate approved step. Initial installation/replacement at the confirmed Mac location, downloaded-app startup and a later real signed update remain separately reported Native results.

## Existing terms and verification limits

The OSAKit archive at version 0.3.2 lacks an in-crate LICENSE/NOTICE, but the retained exact root statement declares the alternatives and the repository already includes complete Apache terms. Its original `referenceOnly` label, bytes, URLs, hashes and SDK/copyright uncertainty note are preserved. `termCompletenessEvidence` explicitly scopes use of that retained text to checking completeness of the package-declared alternative. It is bound to the full pinned material adoption hash and recorded in the packaged inventory. It neither assigns Apache licensing to all generated SDK material nor certifies legal clearance.

The non-reference upstream root statement remains required. Source/VCS/lock/material/SDK hashes, complete-term checks, all other reference-only exclusions and path/source protection remain enforced. Missing or changed terms/records and references outside the package declaration still fail. New dependency material must be included; this preparation does not broaden interpretation research or remove existing notices.

Static tests cover the real supplied public identity/default boundary, command separation, every-file material tampering/omission and scoped OSAKit evidence/rejection. They do not establish a completed Mac build, enrollment status in a running app, production artifact signature, live feed, installer/relaunch or saved-data preservation.
