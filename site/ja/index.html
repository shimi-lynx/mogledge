起動・更新の前に

Windows版にはコード署名証明書がありません。Mac版はアドホック署名で、Appleの公証を受けていません。OSの保護機能によって起動やアプリ内更新が止まる場合があります。更新用の暗号署名は別途検証されますが、OSのコード署名を代替するものではありません。

HTMLファイルを、
いつもの道具に。

専用フォルダーに、HTMLツール、画像などの素材、AI向けの作成ガイドをまとめられます。プロジェクトごとに複数のフォルダーを作成・登録し、表示するフォルダーを選びます。HTMLそのものは、エディターや外部のAIで作成します。

02 / 並べて見る

ふたつの画面を、
一緒に。

資料を読みながらダッシュボードを確認する。タブや2列表示で文書を開き、動作中のHTMLの状態を保ちながらツールを切り替えられます。

画面に残っている状態は、保存済みのバックアップではありません。残したい入力は、それぞれのHTMLツールが明示的に保存する必要があります。

03 / AIに送る

次のアイデアを、
依頼の下書きに。

ファイルやフォルダーを右クリックして「AIに送る」を選び、依頼を入力します。対応するChatGPT / CodexアプリやClaude Codeへ未送信の下書きを渡すか、コピー機能を使えます。

選択したパスや作業フォルダーが依頼の手掛かりになります。ファイルの内容は添付されず、依頼も自動送信されません。送信・実行の前に、下書きと受け取るツールの権限を確認してください。

同梱のSkillsとガイドには、Mogledgeの保存APIやHTML文書IDを扱うための、対応AI向けの説明があります。通常は自分で編集せず、「AIに送る」で希望を伝えます。必要ならローカルのガイドを読むようAIに依頼してください。ガイドの発見や正しい利用が保証されるわけではありません。

04 / 確認してから送信

使うAIツールは、
自分で選ぶ。

Mogledgeは依頼を受け渡し、選んだツールがAIの処理を行います。Mogledge自身がAI APIへ接続したり、文書を自動アップロードしたりすることはありません。

画面例はCodex内の下書きです。Claude CodeやCLI向けの選択肢もあります。受け渡しの可否はOSや受け取るアプリのインストール・設定に依存し、ファイルへのアクセスは受け取ったツールが管理します。

05 / 文書からツールへ

少しのJavaScriptで、
手元の便利な道具に。

ローカルのJavaScriptや相対パスの素材を使うHTMLを動かせます。計算機、可視化レポート、チェックリスト、小さなタスクボードなど。文書保存APIを使えば、HTMLソースとは別にJSONの入力データを明示的に保存できます。

保存処理はHTMLツール側で実装する必要があります。任意のJavaScriptやCanvasの状態が自動保存されるわけではありません。保存済みの入力を正常に復元してから、新しい保存を許可します。

HTMLはサンドボックス内で動作します。

文書のHTMLでは、ローカルスクリプトや対応する相対パスの素材を利用できます。外部サイト、CDN、文書からの任意のネットワーク要求には制限があります。外部リンクは確認後、既定のブラウザーで開きます。

権限と制限（英語） ↗

同じHTMLをブラウザーでも使えますか？

HTMLの内容とブラウザーの対応状況によります。標準機能で完結するHTMLは動作する場合があります。標準の保存アダプターにはブラウザー内のlocalStorageを使うフォールバックがあり、オリジン、権限、容量の制約を受けます。

ブラウザーとMogledgeの保存データは別で、自動同期されません。Mogledge固有のAPIを前提にするHTMLには適切な代替処理が必要です。ブラウザー向けの任意の保存コードを、そのままMogledgeで置き換えて使えるわけではありません。

起動・更新

最初に開く前に、
知っておきたいこと。

現在の署名について

Windows：0.10.1にはWindowsのコード署名証明書がありません。Mac：アドホック署名で、Apple Developer ID署名と公証はありません。

セキュリティ警告、起動のブロック、アプリ内更新の失敗が起こる場合があります。すべての端末で起こるわけではありません。更新機能が検証する別の暗号署名は、WindowsやAppleによる発行元の信頼を示すものではありません。

旧My Knowledgeから更新する場合、0.10.0以降のMogledgeは別のプロファイルを使うため、以前の設定や保存入力は自動でコピーされません。Macでは更新前に旧アプリのログイン時起動を無効にし、必要なら更新後のMogledgeで有効にしてください。置き換える前に更新ガイド（英語）を確認してください。

失敗した場合は、警告文をそのまま控えてください。更新の失敗だけでは、旧アプリが変更されていないことや、元に戻ったことは確認できません。

起動・更新に失敗したら

  1. 公式Releasesから、バージョンとCPUに合う配布物を取得します。公開チェックサムを確認し、元の警告を残します。
  2. 固定のインストール先と、ショートカットやDockの起動先を確認します。未保存の入力を保存して終了（Quit）し、アプリが完全に終了したことを確認します。常駐時はウィンドウを閉じても隠れるだけの場合があります。
  3. 終了後にHTML、素材、保存データのプロファイル全体と旧アプリを別途バックアップします。更新を通すために設定やデータベースを削除しないでください。
  4. 手動で復旧する場合は、検証済みの新しい版を同じ場所に置き換えます。Macは.app全体を置き換えます。Windowsは同じインストール先を使う公式インストーラー、またはアプリのみの置換ガイドに従います。
  5. 導入済みバージョンを確認して、固定の起動先から開きます。保存入力を確認してから利用を再開し、復旧を確認できるまでバックアップを保持します。

起動を強制するためにセキュリティソフトを無効化したり、隔離属性を一律に解除したりしないでください。検証、保存、終了に失敗した場合は置き換えを止め、警告を調べます。詳しくは更新・ロールバックのガイド（英語）をご覧ください。

AIツールに調査を依頼する。

症状、OS、アプリのバージョン、正確なエラーを、普段使うAIツールに伝えると調査の助けになる場合があります。解決が保証されるわけではありません。共有前に内容を確認し、個人のパス、非公開の文書、認証情報などの秘密を取り除いてください。

Macでの起動について

ローカルでビルドすると、ダウンロードしたMacアプリの隔離属性に由来する一部の起動問題を避けられる場合があります。ただしAppleの公証は付与されず、権限、セキュリティ警告、アプリの不具合の解決も保証されません。

通常のソースビルドではアプリ内更新は無効です。後から手動、または更新機能が有効な配布版を通じて公開アプリに置き換えると、その配布版の署名と起動条件が再び適用されます。HTMLと保存データのバックアップを保持してください。
