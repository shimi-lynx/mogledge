FOR WINDOWS AND MACOS

Local HTML viewer.
Windows & macOS.

Open local HTML files in a folder tree, tabs or two columns. Keep documents, dashboards and mini apps together, with optional AI handoff and explicit input saving in supported HTML tools.

Before you open or update

Windows is not code-signed. Mac builds use ad-hoc signing and are not Apple-notarized. OS protection may block startup or an in-app update. Updater signatures are separately verified; they do not replace OS code signing.

Read a reference beside a dashboard. Open documents in tabs or two columns and move between tools while keeping their live HTML state.

Live state is not a saved backup. Each HTML tool must explicitly save the input you want to keep.

03 / SEND TO AI

Give your next
idea a starting point.

Right-click a file or folder, choose Send to AI, and enter your request. Hand an unsent draft to a compatible ChatGPT / Codex app or Claude Code, or use the copy options.

The selected path or working folder provides context. File contents are not attached, and the request is not automatically submitted. Review the draft and the receiving tool’s permissions before sending or running it.

The included Skills and guide are instructions for compatible AI tools, covering Mogledge’s saving API and HTML document IDs. You normally do not edit them: describe your idea with Send to AI. If needed, ask the AI to read the local guide; discovery and correct use are not guaranteed.

KNOW YOUR WORKSPACE

Local files, clear boundaries.

Documents stay sandboxed.

Document HTML can use local scripts and supported relative assets. External websites, CDNs, and arbitrary network requests from documents are restricted. Confirmed external links open in your browser.

These restrictions apply to document HTML. The desktop app’s update checker separately uses network connections to check for and download updates.

Supported boundaries ↗

Can the same HTML run in a browser?

It depends on the HTML and its browser support. Self-contained HTML using standard browser features may work. The canonical storage adapter has a browser-local localStorage fallback, subject to browser origin, permissions, and quota.

Browser data and Mogledge data are separate and do not automatically sync. HTML that expects Mogledge-specific APIs needs a suitable fallback; arbitrary browser storage code is not a drop-in replacement inside Mogledge.

START & UPDATE

A few things to know
before the first launch.

Current signing status

Windows: the 0.10.1 build has no Windows code-signing certificate. Mac: the app is ad-hoc signed, without Apple Developer ID signing or notarization.

Security warnings, blocked launches, or failed in-app updates can occur; they do not happen on every device. The updater verifies separate cryptographic signatures, which do not establish Windows or Apple publisher trust.

Upgrading from the old My Knowledge app? Since version 0.10.0, Mogledge uses a separate profile; previous settings and saved inputs are not copied automatically. On Mac, turn off login startup in the old app before updating, then enable it in Mogledge if needed. Read the update guide before replacing the app.

Keep the exact warning if something fails. A failed update does not prove that the old app was left unchanged or restored successfully.

If opening or updating fails

  1. Get the matching version and CPU build from official Releases. Check the published checksums and keep the original warning.
  2. Confirm the app’s fixed installation location and its shortcut or Dock target. Save pending input, use Quit, and confirm the app has fully exited. Closing a resident window may only hide it.
  3. Keep independent backups of your HTML, assets, and complete saved-data profile after exit, plus the previous app. Do not delete settings or databases to make an update work.
  4. For manual recovery, replace the app at that same location with the verified new version. On Mac, replace the whole .app bundle. On Windows, use the official installer for that same location or follow the app-only replacement guide.
  5. Verify the installed version and launch the fixed target. Check saved input before continuing, and retain backups until recovery is confirmed.

Do not disable security software or blindly clear quarantine to force a launch. If verification, saving, or exit fails, stop replacement and investigate the warning. See the full update and rollback guide.

Ask an AI tool to help investigate.

Share your symptoms, OS, app version, and exact error with your preferred AI tool. It may help identify a fix; resolution is not guaranteed. Review the text first and remove personal paths, private document content, credentials, and other secrets.

OPTIONAL / DEVELOPMENT SETUP

Build from source,
if you prefer.

Most people should start with the ready-made downloads above. Building locally is an optional route that requires development tools and some setup.

Start with the official guide.

Choose the version you intend to use from the source repository. Set up Node.js and the repository’s pinned Rust toolchain, then follow the first-build guide for your OS and CPU.

Windows also needs MSVC C++ Build Tools, Windows SDK, and WebView2. Mac needs Xcode Command Line Tools. The guide lists the supported versions and full commands.

About Mac launch behavior

A local build may avoid some launch problems tied to quarantine attributes on downloaded Mac apps. It does not provide Apple notarization or guarantee that permissions, security prompts, or application bugs are resolved.

Ordinary source builds have in-app updates disabled. If you later replace your build with a released app, manually or through an enrolled updater, that release’s signing and launch conditions apply again. Keep your HTML and saved-data backups.
