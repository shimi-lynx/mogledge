# Mogledge HTML authoring

Use this skill for an explicitly requested HTML mini app or conversion of an existing HTML's persistence. It applies to this selected production folder's authoring workflow, not to development or building of Mogledge itself. Follow the user's existing instructions and preserve their original files.

1. Read [the self-contained guide](../../../.my-knowledge/html-authoring/GUIDE.md) and [the complete template](../../../.my-knowledge/html-authoring/template.html), resolving these paths from this SKILL.md's directory. They are the local kit; no app-source repo, npm, external script or global install is required. If either file is missing, report it and use an available approved complete template; do not fetch arbitrary dependencies or overwrite existing instructions.
2. Copy the complete template to a **new, user-chosen HTML output**. Keep its first two inline adapter scripts, `MyKnowledgeStorage` then `MyKnowledgeExport`, unchanged and in order. Change the UI and last script only as needed. The finished HTML must run without this kit directory. Never overwrite the kit template, another HTML or another app's state as a shortcut.
3. Define a stable `appId` (ASCII letters/digits/`.`/`_`/`-`, 1–80 characters), positive integer `schemaVersion`, persisted fields and validation. Preserve an existing app's identifier/schema unless an explicit migration was designed. Use `MyKnowledgeStorage.create({ appId, schemaVersion })` and await `read()` before validation, restoration, calculation or automatic saving.
4. Keep controls disabled during the initial read. If reading, schema validation or restoration fails, show the error, allow local computation where useful and **disable saving**. Never write defaults over unverified existing state. For later errors retain the input and mark it unsaved. A Save button cancels debounce, awaits `write(latestState)` and then `flush()`; unloading is not a save guarantee. `remove()` is an explicitly requested deletion, never a restore-error workaround.
5. A Native descriptor selects only Native transport, including when unavailable. **Never silently fall back to localStorage after Native failure.** Native defaults are document 5 MiB / profile-wide active 512 MiB; only main settings can explicitly select both limits within 1–8,589,934,591 whole MiB, total at least document. This is a safe-integer byte conversion range, not a guarantee of saving that capacity. Count all appIds, keys, schema/data and JSON escaping. The descriptor’s `maximumDocumentBytes` is queried runtime SQLite capacity, not current quota; the canonical adapter accepts positive safe-integer bytes and Native makes the final quota/capacity/resource decision. Preserve saved values and local input on `QuotaExceeded`, `CapacityExceeded` or `ResourceUnavailable`. Legacy descriptors without that field and normal browsers retain 5 MiB; invalid fields fail closed and browser origin quotas may still reject. Do not add quota queries/writes or change limits from HTML. Keep 128 appIds / 4,096 historical identities and the separate 512 MiB / 4,096 recovery budget; quarantine above that budget is refused safely, not a normal-write cap. A first different setting that creates or rebuilds the old numeric DDL requires an independent whole-profile backup and explicit compatibility acknowledgement. GET/unchanged settings preserve format; restoring 5 / 512 does not restore old-app compatibility. Existing 8 MiB / 5 MiB / 64 KiB inline adapters need approved regeneration, original preservation and explicit identity handoff. App updates do not rewrite them. Logical quota does not guarantee SQLite, disk or memory capacity; Blob export stays separately capped at 5 MiB. Never truncate or initialize failed values.
6. Keep the HTML sandbox: no arbitrary Native IPC, SQL, filesystem or parent-window access, external CDN, shell commands or permission changes. Treat user text, filenames and paths as data, not executable code. Preserve originals when changing HTML identity; use Mogledge's explicit previous-input-state confirmation when appropriate, not automatic state migration.
7. Verify a dedicated fixture's normal-browser save/reload and calculation, plus fake Native restore success, read/schema failure without writes, and write failure without localStorage. Record real Mogledge/WebView/Windows/macOS operations only if performed. Do not use the user's production folder for test writes or send their files/state to an AI service without instruction.

## Generated-file export

Input JSON persistence uses `MyKnowledgeStorage`; generated files use the separate `MyKnowledgeExport.exportArtifact({ blob, name, format })`. Only `png`, `jpeg`, `csv`, `json` and `text` are accepted, with a non-empty Blob up to 5 MiB and a proposed name up to 1,024 UTF-8 bytes. Pass no URL, filesystem path or Native ID. Do not disguise SVG/HTML as an image or truncate output. This API does not export a database, HTML original or replace standard media APIs.

Call directly from a real click/key gesture, never timer, initialization, automatic save or synthetic click. Prepare asynchronous Canvas Blobs before enabling the button. Native export requires the main app's independent confirmation and OS destination picker, creates a new file without overwriting, and does not open it automatically. Browser download is allowed **only when the injected export bridge is absent**; a present but unsupported/denied/failed bridge never falls back. Show `saved`, explicit `cancelled` and `download-requested` distinctly: browser download is not proof of persistence. An unknown result or `ArtifactPublishedUnconfirmed`/`ArtifactResultUnknown` may leave a file behind; keep input/calculation intact, ask the user to check the chosen destination and never automatically retry. Test gesture, limits and these failure boundaries using an isolated fixture. Keep input-save and file-export feedback separate.

## Local media

Use standard audio/video elements and relative `.mp3`/`.mp4` paths inside the allowed root; keep sibling assets together in ordinary HTTP-browser use. Start playback and create/resume a timer's `AudioContext` from a real user click. Hidden/background/sleep timer audio is not guaranteed. Media is separate from input JSON and file-export APIs. Native media files are limited to 1 GiB; each single Range response is a bounded subset up to 2 MiB, so verify the engine requests later ranges. No-Range GET above 2 MiB returns 413. Never fetch/cache the whole large file to bypass this boundary. Windows/macOS Native codec and playback support remains unverified without real testing; record Chromium separately. Do not change CSP/sandbox/root permissions or auto-fetch unavailable cloud assets. YouTube stays external-browser-only. An HTML with relative sibling media is not a self-contained single-file artifact.

If asked to build the app, kit setup remains optional: explain the destination root and obtain explicit choices for (1) guide/template, (2) both project skills, and (3) guide-read instructions in future handoffs. A build alone grants none of these writes. Existing consent for the same choices/root is sufficient. Do not overwrite AGENTS.md, AGENTS.local.md, CLAUDE.md or existing unrelated skills. Initial setup creates new files only, or confirms unmodified same-version owned files. Keep older or edited files intact, report conflicts and skip them; updates require separate preservation and manual review. Use the app's manifest-aware setup rather than copying over files. Ordinary build scripts must not noninteractively write a user's root. This skill itself does not install or reconfigure either AI.
