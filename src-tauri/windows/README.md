# Windows installer template

`installer.nsi` derives from the official [Tauri `tauri-v2.12.1` NSIS template](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.1/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi). The unmodified source has SHA-256 `dabed59013b1d78b879a1a85bc7f2eed2993b33a9a90cdabe5946de3d3950597`. Tauri distributes it under MIT or Apache-2.0; this copy uses the included [MIT license](LICENSE-MIT).

Current installations use `Mogledge` for display, Uninstall/product registry keys, installer language, default directories and autostart. The executable is `mogledge.exe`; the bundle identifier is `com.shimilynx.mogledge`.

The installer reads the exact previous `My Knowledge` product keys only to detect an owned installation. Publisher, recorded executable name, exact uninstaller command and both installed files must match before overwrite upgrade is allowed. Unverifiable predecessors stop installation. An existing fixed/custom install directory is preserved, including a previous default directory whose basename is still `My Knowledge`; a different directory requires a separate uninstall first. A fresh installation uses Mogledge directories. No old profile or document-data directory is searched, copied or deleted by this compatibility path.

After copying the new executable, overwrite upgrade retargets owned shortcuts and the exact old no-argument Run command, writes the Mogledge product registration and removes the verified old installer registration. Foreign shortcuts and Run commands are preserved; a conflicting Run command stops the upgrade before file replacement. A foreign new-name shortcut can leave an owned old-name link in place, retargeted to the new executable. This collision exception avoids replacing another application's link. Existing shortcut targets named Mogledge are also retargeted when they point to the old binary. Normal uninstall-before-install can disable autostart through the old uninstaller, as in upstream; overwrite and `/UPDATE` preserve the enabled registration. The installer relaunches the new executable.

Keep the upstream template changes limited to these compatibility requirements. Reconcile this file with the official template whenever the Tauri CLI/bundler version changes. Native compilation, NSIS compilation, and Windows install/upgrade/uninstall checks have not been performed for the identity change. Before release, verify fresh/default/custom locations, normal and `/UPDATE` flows, new-binary relaunch, version comparisons, registration cleanup, shortcut collisions and autostart enabled/disabled states. Static source checks cannot establish a working installed update.
